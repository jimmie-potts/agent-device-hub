## Context

Hosted tool filters skip record-target and fixed-owner operations. The catalog presently checks English after a model has already chosen a structured tool call. The reviewed Wemo path captures the authenticated current request and clarification by revision before model transport.

## Goals / Non-Goals

Use the same request scope and existing guarded dispatch for the remaining supported catalog. Keep preferences and private catalog records local. Lighting power, brightness, color and temperature, and broader completion reporting retain their own work.

## Decisions

- Keep configured tool names and payload shape. Bind migrated operations to the same request proof as Wemo. Check the admission proof again before a new effect.
- Resolve registered routes locally. Device ownership and target guards come from device state. Record targets carry the owner's revision. Fixed routes retain the exact owner target. Drafts retain the local cue and revision checks.
- Keep the external field policy. Use current owner-entered selectors and resolve them locally. A denied catalog read returns no private record. Store results for the authorized Conversation owner.
- Keep paid artwork and coding behind their explicit approvals. Preserve prior receipts, the tracked dispatcher, deadlines, and unknown-result handling across restarts.

## Risks / Trade-offs

Making commands visible requires fresh request and target checks even for fabricated tool calls. Local records without a unique permissible match require clarification. User-facing receipts remain private if the external sharing policy excludes their fields.
