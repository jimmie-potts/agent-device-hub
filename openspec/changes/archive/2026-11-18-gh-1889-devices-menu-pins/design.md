## Context

The Devices directory already projects every device and module page from the module catalog and the device copies (`directoryEntries`). The rail (#1887) and the palette (#1888) are in place. The owner's accepted prototype opens a menu from the Devices row and keeps pinned pages in the rail.

## Decisions

- The menu is a projection in `device-menu.ts` over `directoryEntries`. Lighting, Displays and Audio are one column and Other the second; a category with nothing to show is left out. A module with several pages is a heading over them, and a page named like its module is "Overview". A module with one page is that page under the module's name. Each address appears once, so two playback modules give one Music entry.
- A module that is not running is named with its state and offers no page in the menu. A running module with stale observations keeps its pages and is marked stale. The directory keeps the full warnings; the menu only avoids presenting such a module as available.
- The Devices row is a button, not a link: an ordinary press opens the menu and does not navigate. The four other destinations stay links, and "All devices" in the menu is the ordinary link to the directory. The row stays marked as the containing destination on every page under Devices, as the five-destinations requirement asks. On a page that has its own row among the pinned pages, pinned or temporary, the mark is drawn without a box, so the rail boxes one row. A page under Devices with no row of its own, such as the Conversation page, a Music source page or the visualizer, leaves the box on Devices.
- The menu uses the menu roles: it opens with focus on the open page's entry or on its first entry, the arrow keys step and wrap, Home and End go to the ends, and Escape closes it with focus on the row. It is not modal. A press outside it, a press on the row, a chosen page, the palette's opening key and focus moving elsewhere close it. While it is open it reads Escape and the arrow keys from a capturing listener on the window, so the phone drawer under it does not close on the same Escape. A press on a heading inside it does not move focus, so the keys keep working.
- A press or a focus move inside a framed module page never reaches the shell's document. The shell's window loses focus to the frame instead, so the menu also closes when its window loses focus and the focused element is a frame. A window that loses focus to another application keeps the menu.
- With focus on nothing while the menu is open, which Tab from the menu's last stop gives in the phone drawer, the arrow keys still work and start from the ends.
- A menu removed while it holds focus, by the browser's back or forward or by a window that crosses the phone width, hands focus on from its own cleanup, which runs while the menu is still in the page: to the Devices row, or at phone width to the drawer's button. That hand-off does not scroll, because in a short window the row can be out of view and scrolling to it would move the page under a press or under the browser's return to a scroll position. A press on the row closes the menu with focus set on the row, since not every browser focuses a button that is clicked.
- The menu is fixed to the window beside the rail. A short window lets the rail scroll away with the page, and a menu positioned against the rail would go with it. It is as tall as the window at most and scrolls inside. A focused entry draws its ring inside the row, where the menu's scrolling cannot cut it.
- At phone width the menu covers the drawer as one column with its own close button. Closing it leaves the drawer open. A chosen page closes both, and the drawer returns focus to its button as it does for any destination.
- In the icon rail the Devices row's name is shown beside the icon on hover and focus. While the menu is open that name is made transparent, because the menu opens in the same place; it stays in the page, so the row keeps its accessible name.
- A pin is a page address, kept as a list in `localStorage` under `bunny.dashboard.pins.v1` by a small store in `pins.ts`, the same shape as the rail's collapse preference. A damaged value is no pins, anything that is not a pinnable address is dropped, and refused storage leaves the list working for the open page. A change from another tab is followed.
- A page can be pinned when the shell can name it now: each page the directory lists, and each device's own page, which for a light is reached from its brand page and is not in the directory. The Conversation page is excluded, as in the prototype; #1890 gives conversations their own group in the rail. The header toggle is shown only on a page that can be shown as a pin, so a pin always appears.
- A saved pin whose page is not declared now is not shown and is not removed. The catalog is read after the page loads and a module can be absent for a while; removing the pin would lose the owner's choice. The hint that explains pinning is shown only when the saved list is empty, not while saved pins wait for the catalog.
- A page of a module that is not running is still a page: its pin keeps its row and the header keeps its toggle. The row shows the module's state in place of the module's name and in its accessible name and title, so the rail does not present it as available. The state keeps its width and a long page name is cut instead; the page itself says that it is unavailable.
- A pinned row is a link with a two-letter mark, the page's name and, for a page of a module with several pages, the module's name. Its unpin button shows when the row is pointed at or the button has keyboard focus. The page that is open and not pinned is a dashed temporary row whose pin button is always shown. After a row's button is used, focus stays on that row's button when the row is still there, and otherwise moves to the row before it or to the Devices row.
- The pinned list takes the room between the destinations and the foot and scrolls inside it. A longer list never makes the rail taller.
- The shell measures whether the rail fits its window (`useRailShort` in `rail.tsx`) and marks the shell when it does not; the stylesheet then lets the rail scroll with the page. Earlier stories named a height for a connected session and another for an ended one. What the rail needs depends on the fonts: in the Linux test container the control-mode line and the pin hint each wrap onto one more line than on a Mac, so the rail needs up to 40px more there, and a named height was right on one computer only. The measured need is the rail's parts and, of the pinned pages, their heading with one row and the room for that row's focus ring, or with the hint when nothing is pinned: about 611px for a connected session on a Mac and about 663px for an ended one. It is measured after each render of the shell, which renders everything in the rail, and when the window is resized. In the phone drawer, which scrolls as a whole, the pinned pages keep at least 70px, and the temporary row's pin button, which is always shown, is a 44px target.
- In the icon rail a pinned page is its mark. The name is the link's title there, not the rail's own hover label: the list is a scroll container, which would cut a label drawn beside it. The unpin button is hidden in the icon rail; the page's own toggle unpins.
- The lighting-brand heading holds its name, the toggle and Arrange. Its two actions are one group that moves under the name when the row is too narrow, so the name is not squeezed at phone width.
- With the measurement, an ended session needs no rule of its own: its "Sign in again" button is part of what is measured. The shell root's `data-session` attribute, which that rule used, is removed. Agent status cards use that attribute name for a session id.

## Risks and tradeoffs

The Devices row no longer opens the directory with one press, and a modified click on it no longer opens the directory in a new tab; "All devices" does both. The rail scrolls with the page in windows about 50px taller than before, so that the pinned list is never a sliver. Whether it fits is decided by a measurement in script, so the stylesheet shows the earlier state until the shell has measured again, within a frame or two of a resize. A pinned page of a stopped module keeps its row, marked with the state, and opens a page that says it is unavailable. Reordering pins, pins shared across browsers and pinning from inside the menu are deferred on the issue.
