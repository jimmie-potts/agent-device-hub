## Context

The worker credential binds an SDK source to one gateway connection and endpoint. The existing coordinator stores the active endpoint in a single slot and persists attempt, result and stop receipts in SQLite. The tracked dispatcher already records operations before delivering a start.

## Goals / Non-Goals

Each approval chooses an execution destination independently of its harness. Installation, device commands, provider setup, cross-host worktree transport and host qualification have separate owners.

## Decisions

| Approval and observation | Eligibility or rank |
| --- | --- |
| Existing single-Mac grant and legacy declaration | Preserve the existing route for ordinary work. |
| Pinned Windows step with the approved revision on PC | Only a fresh matching PC declaration and permitted brief can run. |
| Same revision on two allowed hosts | Prefer available test resources, lower pressure and usable quota. Equal observations use stable destination identity. |
| Installed operation or physical proximity | Require trusted operator or location binding. An edge-routable check can name separately authorized destinations. |
| Router cannot confirm the account, revision, source or sharing | Show the failing condition and eligible alternatives before dispatch. |
| Link disappears after delivery could have occurred | Keep the original attempt uncertain. Other connections continue independently. |

Keep live endpoints in a registry keyed by authenticated destination. Use the existing endpoint incarnation and immutable request ID for dispatch, progress, messages, stops and native controls. Persist the requested and selected destinations, revision and reason with the attempt. A new connection never resumes an earlier writer by inference. Share the existing coding state publication with additive roster information and continue reading earlier schemas. Current test hosts apply the verified Mac and PC profiles from #1681. Test slots affect test work; the uncapped worker has no arbitrary coding job ceiling.

## Risks / Trade-offs

Host pressure and account status can change after selection. Recheck before delivery and require the worker to verify the pinned Git object before executing. Remote enrollment does not establish provider support or device authority. The established Mac rollout cannot reconstruct declarations or prior destination choices that old data never recorded.
