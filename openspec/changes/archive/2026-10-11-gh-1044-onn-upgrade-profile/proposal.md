## Why

Configured or retained ONN state is outside the current runtime upgrade profile, so the accepted controls and title-history source cannot yet be installed under that procedure. This supporting source slice for [#1044](https://github.com/jimmie-potts/agent-device-hub/issues/1044) qualifies the fixed ONN owner while keeping installation, client and physical acceptance separate.

## What Changes

- Admit the existing ONN configuration, private module directory and SQLite sidecars through the current inventory-only state inspector.
- Require ONN baseline/candidate/compatible-recovery/re-upgrade coverage in the existing private admission certificate whenever ONN is configured or retained.
- Require configured ONN health; preserve the exact absent-ONN exception and conservative unknown/wrong-state refusals.
- Verify retained synthetic title originals, reported progress, gaps, private request identities, command fences and outcome outbox across four separate-process phases without replay.
- Integrate with BB-8's accepted fixed paired profile, preserving legacy certificate sets and its requirements.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `bunny-runtime-upgrades`: configured/retained ONN coverage and compatible latest-state proof become part of the fixed production profile.

## Impact

Scoped changes to runtime upgrade inputs/admission/preflight/source anchors, owning tests, UPGRADE and development checks. Existing ONN storage and SDK outbox are reused. No root dependency, lockfile, device transport, native artifact, installer framework or collection-source change is planned. Source checks use synthetic private state; actual release qualification, running identity and owner-observed acceptance remain required before #1044 closes. No fresh device authority is selected.
