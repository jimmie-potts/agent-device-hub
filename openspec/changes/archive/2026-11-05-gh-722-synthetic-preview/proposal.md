## Why

The operator can measure Music input but cannot inspect the five reactive effects before choosing a real lighting session. A bounded synthetic preview lets the operator compare colors and intensity while light admission and physical qualification remain separate.

## What Changes

- Add five explicit version-one built-in recipes and an unsaved palette/intensity draft inside the existing Nanoleaf Wall page, linked from Audio.
- Prepare twenty RGB snapshots for fixed example Lines or NL22 geometry through the existing authenticated module-content read interface, using the unchanged Music renderer.
- Require explicit Preview, keep scrubbing local, reject invalid requests and fence results after edits, disconnect or unmount.
- Keep custom preset persistence, live/calibrated input, configured geometry, device participation and actual execution unfinished under their existing owners.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `nanoleaf-module`: bounded synthetic Music recipe preparation and explicit preview in the shared Wall interface.

## Impact

Owning issue: https://github.com/jimmie-potts/agent-device-hub/issues/722, within the selected #720 goal. Nanoleaf owns preparation and UI source. The existing SDK module-content interface and registered errors are reused. There is no controller-contract, event-family, core-state, storage, collection, dependency or device-writer change. Existing static favorites cannot store reactive recipes unchanged and are not extended by this increment.
