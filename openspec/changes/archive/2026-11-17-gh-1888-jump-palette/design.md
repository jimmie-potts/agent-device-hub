## Context

The shell already holds everything a page list needs: its own routes, and `directoryEntries`, the projection the Devices directory draws from the module catalog and the device copies. Story #1887 left room for a field in the rail.

## Decisions

- The list is a projection in `jump.ts`: the shell's destinations, then each link of each running directory entry, once per address. It reads nothing new. An entry whose module is not running is left out. Like the directory, the list does not ask whether a listed page can be shown right now; a framed page still opens as unavailable while the feed is down.
- Recent pages are kept in a ref for the page session. The shell records the page it leaves, and the palette shows up to three that the current catalog still offers, without the current page. They are not saved; recents that survive a reload are deferred on the issue.
- The key rules are one pure function, `jumpShortcut`, called from a `keydown` listener on the window. The listener ignores a key a component already handled. Command and K or Control and K toggles the palette anywhere. On a Mac, Control and K in a text field deletes to the end of the line, so it is left alone there; the Conversation composer is such a field. A slash opens the palette only outside a text field and outside an open menu, list or dialog. A text field is a `textarea`, a `select`, editable content or an `input` of a type that takes typed text; a slider or a checkbox keeps focus after it is used, and a slash there is not text.
- The palette is a `role="dialog"` element with the rest of the shell made inert, as the phone drawer does. While a modal `dialog` element is open (Conversation Details at phone width) or an element is shown with the Fullscreen API (the visualizer's full screen), the palette could only render out of sight, so its keys do nothing until that ends. The palette and its scrim are stacked above every level the page uses, so the palette is drawn over the full-window visualizer, which is a fixed element inside `main`.
- While it is open the palette reads Escape, the arrow keys and Enter from a capturing listener on the window and stops them there, so they work wherever focus is and nothing behind the palette reacts. Any other key pressed with focus outside the field returns focus to the field. A press inside the palette that is not on the field does not move focus, and the scrolling list is not a Tab stop.
- The list follows the choice only when a key or typing moved it. The shell renders every second for its clock, and a list that followed the choice on every render could not stay scrolled by touch or wheel. The list the palette receives is memoized on the catalog, the copies and the page; the shell's route is one object per address so that it can key the memo.
- The chosen row has a boundary as well as a tint. The tint alone is about 1.2:1 against the palette.
- Closing returns focus to the element that had it. When the palette is opened from the phone drawer, the drawer closes underneath, so focus returns to the menu button.
- A page change the palette did not make, from the browser's back or forward, closes the palette. It was opened over the page that was left, and its recent list and focus target belong to that page.
- The palette and the navigation links share one `navigate` function, so a page chosen in the palette also opens at its top. Focus then moves to the page, as it does after the skip link.
- The filter keeps an entry when every typed word appears in its name or its hint, the two things a narrowed row shows. A name that starts with the query ranks first, then a name that contains it, then a match in the hint. The group label is not searched: a narrowed list hides the group headings, and "pa" would otherwise keep every device page. A query drops the Recent copies so a page is listed once.
- The key hint in the rail and the palette's footer of key names are hidden for a coarse pointer, where there is no hardware keyboard to use them.
- The brand's second line needs more width than the 44px toggle leaves in the 184px rail, and wrapped. The brand now starts at the column's edge and the head borrows 8px of the rail's padding, which is enough for one line. The toggle keeps its 44px target and draws a 34px box, so its hover and disabled states stand clear of the line. The phone drawer has no toggle and keeps the brand's earlier inset.
- The jump field adds 60px to the rail. A connected session's rail now needs about 531px and an ended session's, with "Sign in again", about 571px, so the height below which the rail scrolls with the page is 560px for a connected session and 590px for an ended one. One height for both would take the in-view rail from connected sessions in windows where it fits.
- The toggle's focus ring is drawn on its 34px box, for the same reason its hover box is.
- The palette ignores an Enter that is still held from opening it. The rail's field is a button, which a held Enter presses first; the repeat would otherwise choose the first row.

## Risks and tradeoffs

Making the page inert takes focus from the control that had it. A control that commits a pending edit when it loses focus, such as a brightness slider with an arrow key still held, commits it then, as it would on any other loss of focus; the palette itself sends nothing. A key pressed inside a framed module page does not reach the shell, so the shortcuts do nothing while focus is in such a frame; the rail's field and the phone bar's button still open the palette. On a Mac, Control and K opens the palette outside text fields only, which differs from Command and K by design.
