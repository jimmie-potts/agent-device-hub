# Design

## Context

React unmounts the root on an error no boundary catches, in render, lifecycle or a passive effect. Errors in event handlers and async work never reach a boundary and leave the page mounted; they keep their current behavior. The owner's intent: an error stays in its own card, which shows it, and does not bring down the whole page.

## Decisions

- **Placement.** The boundary sits where module and card content is drawn: around each Home card's content inside its grid cell, around each device card on the component route, around the module page on its route, around the Settings, Companions, Habitat, Timeline, Automation and Connections pages, the always-mounted device directory, the rail's conversations and the art backdrop source. A card's content is passed as a function that the boundary calls in its own child component, so the work that picks a Home card's content or compact state, or a component page's device card, runs inside the boundary. The grid cell is outside the boundary, so a failed card keeps its place and size. The shell (rail navigation, pins, menus and foot, phone bar, jump palette, breadcrumb, Home's layout, hero and edit controls, page headings, tabs and notices, the lighting and playback workspaces) stays outside: a fault there is a shell fault, and its failure state would need its own design.
- **Failed face.** A card shows its name, "`<name>` failed to show. Retry draws it again and sends nothing." and one Retry; a page shows the same under its own heading, in the page's place. A part that draws nothing renders a hidden marker; the device directory does so off its route and shows the page face on it. Retry bumps a key, so the part mounts afresh; it sends no request. A change of identity resets the boundary in the same render (`getDerivedStateFromProps`), so the next part mounts once. A part that throws after Retry is contained again, and nothing retries by itself, so there is no render loop.
- **Record.** `recordCardFault` writes `dashboard.card.failed` through `recordLog`, whose level the SDK table owns (ERROR, an internal fault), with `bunny.card`, `bunny.code: internal` and `error.type` from `errorType`. No message, stack or cause, and no name or label (ADR 0011, ADR 0012 "Safe errors"). The record is formed in the page and delivered nowhere: the diagnostic contract's browser relay is not adopted, so the records stay in a bounded in-page log of 64. The contract makes a new event or attribute a catalog change, a new profile with fixtures, required before a record is exported, and it registers events per service and scope; the page has no registered service or scope yet. Registering `dashboard.card.failed` and `bunny.card` therefore belongs to the relay's adoption, a named follow-up (#2159), and is not done here.
- **Visibility to tests.** The boundary passes the error to `reportError` where the browser has it, and to nothing otherwise (runtime code writes no console output), so journeys that watch page errors still fail. The failed face carries `data-card-failed`, `data-error-type` and `data-fault-count`, which the harness checks at each `feed()` and `copiesSynced()`. From a page's first such check, the harness also watches the page: an observer reports each rise of `data-fault-count` to the test process through a binding as it happens, so the record holds after the page or browser closes, and the world's `close()` fails the run on any failure that no check reported and no journey expected (`expectCardFaults`). It does not throw from `close()`, which runs in each journey's `finally`: it writes the line and sets the exit code, so a failure already on its way out stays the run's error.

## Testing

A test build of the dashboard replaces five imports of the shell with stand-ins that throw on request and count their mounts, and exposes the page's log of records, so no product hook exists for the fault.

## Risks

A fault in the shell itself still unmounts the page, and so does an error thrown from an effect's cleanup as its part leaves the page: React passes it to the nearest boundary that stays mounted, and the part's own boundary leaves with it. The in-page record is lost with the page until a relay exists.
