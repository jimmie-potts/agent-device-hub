## Context

See proposal.md for the outcome. #229 supplies compatible `playback/2.1` with a canonical PNG no larger than 128×128 and 64 KiB and an opaque generation. Both modules already consume 2.0/2.1 synced records and render in runtime workers. Tidbyt's single cloud queue and Pixoo's adapter queue own device admission. Pixoo's browser projection spreads its public playback view, so artwork bytes and tokens must remain separate from that view.

This design is required by the schema: the change crosses two modules, worker completion and serialized device admission, with image parsing, concurrency and recovery risks. It adds no architecture owner or transport.

## Goals / Non-Goals

**Goals:** Keep current observation association through rendering and queued admission; preserve existing text pixels when artwork is absent or refused; keep valid artwork updates within existing display policies and outcome semantics.

**Non-Goals:** Receiver reads, source preference changes, image history, browser artwork, scrolling, a new rotation slot, clock, foreground Tidbyt takeover, new device queues or changes to public event contracts.

## Decisions

1. **Decode in the owning worker.** Use the pinned sharp already present in both packages, promoting Tidbyt's existing development dependency to production. Check canonical base64, 64 KiB input, PNG framing including a single final IEND and no animation chunks, declared dimensions, one page and 16,384 pixels from the first decoder call. Flatten against black, convert to sRGB and contain within 24×24. Decoder refusal returns the exact existing text card; a worker crash or deadline remains failed-render/no-write. A new shared image service or library would add ownership and transport without helping this bounded use.
2. **Keep the text renderer synchronous and unchanged by default.** An owning asynchronous artwork helper composes decoded RGB into the existing card layout. Tidbyt keeps its marker and four text rows, with artwork at (0,8) and nine text columns at x=27. Pixoo keeps its header/divider and seven row positions, with artwork at (0,13) and nine text columns at x=27. Stale image and text are divided by three. Independent decoded goldens qualify geometry, long/missing text and nonsquare containment; a 16×16 Tidbyt region with eleven columns remains an implementation alternative if readability fails review.
3. **Separate visual equality from observation association.** Use the selected owner/record and generation for a private observation token; legacy 2.0 uses a consumer association from its record and observation revision. A visual key includes status, normalized text, stale state and an image digest, never raw base64 in Tidbyt's persisted memory. An opaque generation change alone does not force an identical-frame transmission, but invalidates obsolete work. Pixoo receives artwork in separate private context, outside NowPlayingView and its browser projection. Textual trackKey retains its existing pop-up decisions.
4. **Recheck Tidbyt after waits.** TileWriter checks its captured target after rendering and after installation listing. CloudQueue checks an optional current predicate at queue entry, before authentication holds, after rate-limit waits and immediately before deadline/sending. Guard pushes and removals. Before any actual call, a superseded target restores the pre-render gate and produces no begin, uncertain persistence, failure/backoff or device record. A listing or mutation that actually began retains its real timing, span and outcome; a started mutation cannot be unsent. The existing requested-update loop evaluates the newest target.
5. **Cancel obsolete Pixoo card admission through the existing queue.** Cache and pending render continuations require the current observation and render revision. Previous rendered cards can be retained only within that association, and cannot be newly sent for another track. Each selected card write has a private abort controller combined with Player's signal. Invalidate it on observation replacement or presentation loss, including attention, stop, expiry, setting/mode changes, interruption and close. Player checks eligibility at entry; the existing adapter checks the signal after its queue wait and before each effect. Suppress player observation and presentation failure only for internally superseded cancellation with priorEffects none. Current failures and possible partial effects retain existing uncertainty/recovery; no adapter-generation bump or command replay is added.
6. **Keep diagnostics safe at decisions.** Worker refusal returns only a fixed canonical code to its owner. Report one artwork failure when the code changes and one recovery when ready rendering returns; absent/unsupported contract states are ordinary fallback. Existing worker failure diagnostics, cloud spans and real adapter outcomes remain authoritative. Discarded work is neither a transmission nor a device failure. Bytes, tokens, URLs, text and native exception messages never enter diagnostic fields.

## Risks / Trade-offs

- Reduced text width → Keep font size and row allocation, compare complete synthetic frames and review long/missing text. Preserve the old full-width fallback exactly.
- A queued stale write could pass a render-only guard → Exercise delayed render and blocked adapter/cloud queue cases, including rate holds and removal.
- Internal cancellation could look like a device outage or user takeover → Verify no-effect cancellation preserves player/presentation state; retain partial-effect uncertainty separately.
- Native decoding is outside V8's heap bound → Bound bytes and pixels before full decode and retain the existing worker deadline. These checks do not qualify native heap or thread-termination non-overlap.
- Tidbyt cloud acknowledgment does not prove its next visible rotation → Keep golden, queue and physical evidence separate.

## Migration Plan

No store or public-contract migration is needed. Old text-only records and persisted visual keys remain usable; a changed current frame is evaluated through the existing gate. Deliver both modules in one source PR with a coordinated narrow Tidbyt dependency/lock change. The existing CI commands discover the added product tests; owning guides document focused verification and the physical-trial checklist. Installation uses only the qualified current-runtime upgrade/recovery procedure owned by #1037. Epic #1054 retains installation and separately authorized visible-device acceptance; this story's accepted finish is source-only.
