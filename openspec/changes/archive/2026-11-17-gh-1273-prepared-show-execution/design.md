## Context

[PR #1446](https://github.com/jimmie-potts/agent-device-hub/pull/1446) and [PR #1474](https://github.com/jimmie-potts/agent-device-hub/pull/1474) supply a deterministic cursor and canonical per-zone transition locations. The local show store resolves immutable decorative versions. The existing Music path uses one core session per light, an authenticated work command and the Nanoleaf worker's journal. Its stream and guarded restoration support Lines and NL22. [#1777](https://github.com/jimmie-potts/agent-device-hub/issues/1777) records the known NL22 takeover limit.

## Goals and non-goals

Admit and run an independently clocked saved show on one explicitly selected light. Verify both device families and all timing and interruption cases with fake devices and a controlled clock. [#723](https://github.com/jimmie-potts/agent-device-hub/issues/723) owns the player clock, recording identity, measured route delay and replay UI. This change uses no Apple Music observation, capture feed, new scheduler or qualified physical phase seek.

## Decisions

### Keep authority in the existing Music path

Extend the registered Music lighting control and work command unions with `start-show`, `pause-show`, `resume-show` and `seek-show`. Reuse `stop`. Start names a saved show ID, exact version, initial position in milliseconds and a bounded start delay from 0 to 30 seconds. A delay of zero requests immediate scheduling. The wire carries a duration, so it never compares absolute monotonic timestamps between callers. Transport controls require the current core record revision and the active session generation. Pause, resume and seek use a playing or paused session. Stop can cancel a scheduled Start. The dispatcher's normal work deadlines extend by the bounded delay for a saved Start. The core owns the revision and session generation, allocates a work ID from the initiating request and target, and dispatches through the tracked path. The device owns the cursor's callback generation, distinct from the core session generation. Preserve the existing live Music shapes and behavior.

Extend `LightingControl`, `LightingWork`, `LightingState` and `LightingDeviceState` in `packages/event-contracts/src/v2/music-lighting-data.ts` and their registered schemas. The entry points are the core's existing `music-lighting-control` responder in `apps/runtime/src/core/music-lighting.ts` and the module's `#musicWork` responder in `modules/nanoleaf/src/module/runtime.ts`. Add a prepared variant to the journal's Music Start handled by `playMusic` in `music-session.ts`. Use `MusicTimelineCursor`, `prepareMusicCueFrames` and `locateMusicCuePhase` from `music-timeline.ts`. Resolve the immutable version through the existing reader in `music-shows.ts`. The Nanoleaf module resolves the version inside its own store and validates the whole cue plan against the current saved layout and stream addressability before an external-control write. Validate each cue against existing renderer bounds without retaining all prepared frames at once. Pin the semantic version and layout for this admitted attempt. Prepare frames only for the selected cue and discard them when it changes. A later library edit affects a future Start. Existing worker ownership and layout/configuration revision fences protect admitted work. Refuse a missing version, unsupported layout or stale generation before it can write.

### Use the worker's clock and stream

Keep the existing worker, external-control entry, per-device packet format, status reads, and restoration guards. Adapt only the frame source and scheduled controls in the worker's Music execution path. The module samples its execution clock when it accepts the journaled Start and adds the requested delay to establish the target. The worker waits for that target before writing external-control entry, rechecking expiry and ownership. If entry settles after the target, its first frame selects the initial position plus the elapsed time since the target. A wholly elapsed cue is missed. A show already past its end before entry needs no device write. A deadline that passes before entry uses the existing expiry behavior. A future Start waiting in the queue grants no device write before its target. Pausing freezes the cursor and holds the last frame while the same worker continues checking for takeover and terminal interruption. Resume is explicit within this same paused session. Seek while playing selects the requested position on the next eligible frame. Seek while paused changes the position without a device send. A gap also holds the last frame. A late wake sends only the currently selected sample.

The pure phase helper and its specification continue to return canonical endpoints and durations. One encoding option sends the next canonical endpoint with a transition representing remaining time. That would change both packet encoders, require device-specific quantization and bounds, and ask the light to interpolate from an unknown current output after a seek. For this source proposal, use a new prepared-frame renderer with the existing stream encoding and maximum cadence. Sample each zone's canonical target at the cursor's current phase. When both canonical endpoints are known, the proposed software policy is channel-wise linear interpolation at elapsed transition fraction, rounded to an integer and clamped to the byte range. An unknown initial origin selects the first canonical target directly. A completed one-shot uses its final target. The existing 100 ms transport transition remains in effect. This policy computes repeatable software colors. The device's actual starting color, playback phase, rendering and display timing remain unobserved.

An independently clocked show has no external source lease. Its authoritative source is the in-memory cursor and the runtime's injected clock. The adapter uses the existing runtime-clock seam and treats a backward or invalid reading as source loss, ending the session and applying guarded restoration. The prepared path never depends on the Music capture watchdog. A loss or overflow on a command or ownership stream that makes continuity unknown must fence further sends and end an admitted show as source loss while the worker can still settle. Use existing SDK sync invalidation and module lifecycle signals where present. The shipped core and Nanoleaf module share the in-process runtime, and no recurring work stream feeds a standalone cursor. An operator connection loss alone does not revoke an admitted show. Shutdown or a worker stop fences sends immediately and uses existing restart settlement and no-replay behavior. A device read, write or datagram failure is a device ending. An absent #571 clock leaves standalone replay available and synchronized replay unavailable. Future player-bound execution must supply its own authoritative freshness and discontinuity policy under #723. There is no heartbeat or new poll.

### End without replay

Explicit Stop, alert, clock/source loss and natural completion use the existing guarded base restoration. Natural completion releases the light as an explicit Stop would. A manual choice wins without restoration. Restart, shutdown or transport failure stop sends and preserve the existing uncertain and hold rules. They do not run saved journal work again. Pause is an active session state and never re-enters a session ended by #40. Preserve the scene restorer's current behavior and leave [#1782](https://github.com/jimmie-potts/agent-device-hub/issues/1782) separate.

The NL22 uses the same stream and existing `*Dynamic*` observation guard. A choice that leaves selection, brightness and power indistinguishable from streaming is still undetectable. For saved shows the owner accepted this behavior on 2026-11-17, including the risk that Stop restores the base over an unsaved effect chosen in the app. Source tests cover observable takeover and separate light ownership. [#725](https://github.com/jimmie-potts/agent-device-hub/issues/725) owns installation and physical acceptance.

### Keep scheduling evidence bounded

The work request uses existing typed refusals, tracked acceptance, deadlines and outcome handling. The light journals accepted work before replying. Commands that expire in the queue do not run. If a write might have occurred before a reply was lost, the existing execution journal preserves uncertainty. Duplicate IDs use the existing rejection and outcome acknowledgment rules. There is no resend. Controls that race with Stop, a newer generation or the end of the show settle without further frames.

The device record reports the latest cursor state and cumulative count of wholly elapsed cues that received no scheduled sample. Count distinct cue IDs, up to 256, that wholly elapsed without a sample during a traversal. The same cue may be missed again after a seek, but the count remains a unique-cue count for that session. A cue previously missed remains in the evidence if a later traversal schedules it. Maintain a bounded in-memory set and persist its cumulative count in the session record when it changes. Publish the count through device sync and carry it into the ending so reconnect and restart report the last committed count without replay. Seek skips do not increase the count. Publish state at entry, on transport changes and when the missed count increases. A local packet send records only transmission. The existing trace parent connects operator request, work and command outcome. No new log fields or private show data appear in diagnostic logs.

## Risks and trade-offs

- Whole-plan preflight costs time for bounded large shows. Check command expiry after preflight and before the first write. Retain only one cue's prepared frames during execution.
- Additive Music control and state variants touch strict profile validation. Update schemas and registration, cover the existing live payloads, and validate core, device and dashboard consumers.
- UDP sends cannot be recalled. Recheck generation and interruption after awaits and immediately before each send. One in-flight send may already have reached the transport.
