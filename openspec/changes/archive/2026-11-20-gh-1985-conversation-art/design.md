## Ownership and handoff

Conversation owns the approval and stores at most one artwork attachment on one assistant message per task. The call reservation saves the reference before dispatch, so a lost reply can still resolve to the Art job. That job produces one immutable artwork and one chosen rendition for the attachment. The authenticated art content reader resolves that reference and serves the exact bytes. The browser observes the existing art state and never submits a command while restoring history.

The core admits `art-request/2.1` only from the companions module. It stores a private duplicate digest and omits the approved description from its operation and history. Art owns admission, limits, execution, rendition validation and storage. GIFs reuse its bounded GIF processing. An inline request runs no stage, display or presentation command. A separate owner approval is required before any provider work begins. Art keeps Conversation results beyond the ordinary recent limit. Explicit catalog deletion still removes them.

## Outcomes, faults and diagnostics

The tracked receipt records queue admission. The job reports actual generation success, rejection, failure, cancellation or uncertainty. Approval decline, invalid input and permission refusal admit no job. Timeout or loss after dispatch can leave a job in progress. Neither Conversation nor Art replays work. Duplicate delivery resolves to the existing request and message identity. The browser observes Art revisions while waiting and reads the job by reference. A refused request or an unknown admission stays distinguishable from an unavailable rendition.

The normal command and Art provider spans preserve trace lineage. The originating task, job request and exact rendition identifiers correlate the private records. Attachment reads carry no media into prompts, transcript checkpoints or diagnostics. The former text-only rows keep their existing shape. A separate reference table adds no required fields to existing message records and needs no data rewrite at startup.
