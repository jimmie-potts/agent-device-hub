Lifecycle

  1. Validate configuration, contract compatibility and exclusive state ownership.
  2. Open the owned storage boundary and restore persisted state with correct uncertainty.
  3. Start read interfaces and qualified subscriptions; admit writes only when their owner can safely handle them.
  4. On termination, stop admission and producers, bound draining, retain outcomes and release ownership in a defined order.

Crash and restart

A restart cannot make old observations fresh or turn an unknown write into a confirmed success. Reconnect consumers from snapshots and reconcile retained request identities. Controller queues retain their own lifecycle; hub termination does not imply physical playback stopped.

Verification

Before a real deployment, test overlap during rollout, forced termination after dispatch, restart with stale task state, storage failure and unavailable device adapters. Freeze exact manifest settings and startup/shutdown commands under Q-DEPLOY; this page is not a deployable workload.
