Composition proposal

Start the future B.U.N.N.Y. host as a modular backend. Application operations, agent state, playback state and rules may share one process. API/MCP interfaces are entry points. Existing controller processes retain their ownership until their own migration is delivered. Separate document IDs do not require separate containers, databases or services.

Startup and shutdown

Start storage access and the selected state owner before admitting dependent writes. A missing device should degrade that device rather than hold the whole host unready. During shutdown, stop new admission, bound draining, retain operation identities and prevent a replacement writer from overlapping. Exact readiness, timeout and shutdown settings remain Q-DEPLOY.

Migration and reset

A B.U.N.N.Y. owner move quiesces the old owner, exports compatible state, verifies import and switches producers/consumers once. Keep rollback compatible with the selected schema. Restart, container replacement, cluster deletion and deliberate data reset are different operations. VOL-state defines what must survive each.

Verification and entry point

No B.U.N.N.Y. Docker image, Compose manifest, Kubernetes workload or server procurement is delivered here. Runtime commands must be added by Hub #5/#42 after implementation. The only executable entry points added by this work build and check documentation. Server sizing waits for measured host load and Hub #44.
