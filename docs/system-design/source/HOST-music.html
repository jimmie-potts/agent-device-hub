Host and trigger

Apple Music runs in the Windows app selected by the user. A small host-specific connector is the proposed integration point. The concrete Windows API, supported metadata, player-selection behavior and command coverage must be qualified against the installed app. Catalog search is not evidence of local now-playing or playback control.

Boundary and execution

The connector sends bounded selected-player observations to CORE-playback and accepts only supported, authorized playback requests for the configured source. BUNNY may run elsewhere, but the connector still depends on the Windows user/player environment. Docker does not make that environment portable.

Failure and recovery

  • When Windows, the player or the bridge is unavailable, retain old state only with explicit age/unavailability.
  • A playback command with unknown effects must not be silently retried as a new action.
  • Source selection and credentials are explicit configuration. Restart must not attach to an unrelated media session.
  • Audio capture for levels/spectrum requires separate source, permission and cadence qualification.
