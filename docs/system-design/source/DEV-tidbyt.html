Status and connection

The repository contains documentation, not an implemented Tidbyt controller. The accepted first connection uses the official cloud. Keep pure 64×32 WebP rendering separate from connection identity, credentials, delivery outcomes and update limits.

State and policy

The controller consumes interpreted agent state, initially from the core embedded in Pixoo. It owns display layout, session selection, notice handling, rotation, manual takeover and restoration. Music participation adds now-playing cards only after the playback and cloud delivery paths are qualified.

Optional Tronbyt

A future Tronbyt backend reuses the render boundary and writer queue. Firmware/server compatibility and physical transition require separate qualification and authorization. Do not enable two writers or use automatic cloud/server failover.

Verification

Use fake feeds and transport to verify policy before installed cloud and visible-display acceptance. A successful push is not pixel evidence. Cadence and synchronization remain qualification questions; neither the 64×32 format nor a simulator proves music visualizer performance.
