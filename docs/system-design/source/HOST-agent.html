Current and target paths

Existing Nanoleaf-local lifecycle behavior and the delivered Linux baseline are separate from the future shared Hub provider emitters. Codex Desktop, Codex CLI and Claude Code are distinct qualification targets. Fresh shared-hook installation and owner cutover belong to Hub #8.

Execution boundary

  1. Receive the provider lifecycle trigger in the environment that owns that agent execution.
  2. Construct allowlisted metadata before delivery, persistence or diagnostics.
  3. Perform the bounded handoff to the selected state owner, preserving stable source identity.
  4. Return successfully and silently on invalid input, saturation, timeout or unavailable collection. Never wait for a device or emit an agent permission decision.

Placement and migration

The host hook remains beside the agent runtime even if BUNNY later runs in Docker or kind. Containers stay behind the bounded handoff. Only one selected ingestion path updates a session. Legacy installations retain their own behavior until a separately selected and verified cutover. The Nanoleaf fresh Linux migration does not itself install shared Hub emitters.

Failure and verification

Drop new observations on saturation as required by the contract, retain a bounded loss indicator and expose missing evidence later. Do not serialize private provider input into errors. Use the early Linux budget artifact for process/queue/deadline design; installed hooks require real-client checks under Hub #8. Registration alone is not observed lifecycle delivery or visible-device acceptance.
