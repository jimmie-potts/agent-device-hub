State ownership

The Windows connector observes the selected Apple Music player. B.U.N.N.Y.’s playback service interprets those observations into a current playback snapshot. It is a separate logical module from the agent-state core and can live in the same backend process. The app API exposes its reads and supported operations.

Controls and failure

An explicit UI/MCP Next request passes through the application/playback service to the selected Windows connector. It does not pass through agent state or require an automation rule. A timeout after possible dispatch remains uncertain. Re-read player evidence before deciding whether another explicit action is needed. Losing the Windows source makes playback stale/unavailable; it does not stop unrelated local device control.

Verification and open choices

  • Qualify Windows metadata, session selection, supported controls and refresh behavior under Hub #36.
  • Test duplicate observations, same-song repeat/restart, reconnect and missing track identity before promising track-change semantics.
  • Music metadata is an explicitly selected domain. It must not be copied into the allowlisted agent lifecycle feed. Artwork access, caching and retention remain Q-MUSIC.
  • Audio levels and spectrum are a separate input under Hub #41. A track change cannot establish sound intensity or synchronized animation.
