One brain.
One owner for every device.

Today, B.U.N.N.Y. runs on the Mac Mini as one TypeScript process. The core owns shared state and decisions; device modules own their local I/O. A common SDK connects them.

The current runtime

Dashboard, agent hooks and MCP clients enter through the authenticated gateway. Inside apps/runtime, the core and statically shipped modules communicate through the SDK bus using message profile 2.0. There is no external message broker.

Open the interactive runtime diagram. Its October 9 rendering is retained: the owners and connections still match this source review.

Authoritative core

Sessions, inbox, history, action tracking and automations. Core state and related tracking records commit together in private SQLite storage.

Device modules

Each device has one designated writer. Its module owns transport, queues, private state and durable outcome reporting. Other components use SDK calls.

Remote clients

HTTP requests go up; SSE events come down. Clients sync current membership, then follow live changes. Reconnection never replays old commands.

How commands complete

An accepted request means an owner has taken responsibility, not that a device has acted. The core tracks the eventual succeeded, failed or uncertain outcome. Modules persist outcomes before reporting them; the core deduplicates and acknowledges them. Retrying a report never resends the device command. Transmitted evidence remains distinct from physical observation.

Where it runs today

The Mac Mini hosts the Linux ARM64 container on Docker Desktop. PC and phone interfaces use the Mac’s private HTTPS route. Input helpers stay on the computer that can read their selected source.

Module-owned LAN or vendor transport

Normal Mac operation does not depend on the PC being on. PC-local observations can become stale or unavailable while the Mac continues serving its other capabilities. The old WSL device runtime is stopped and retained for a separately authorized manual return.

The October 31 Mac cutover records the accepted integrations and their limits. Module source or healthy transport does not establish every device’s physical qualification. Startup follows manual FileVault unlock and sign-in; there is no automatic failover.

Accepted direction · not deployed

A cloud brain with local device edges

ADR 0016 moves toward a single cloud-hosted brain owning state, history, inbox, automations, APIs and MCP. Local edges keep device drivers and host input helpers near their hardware and sources.

Target flow: interfaces and input helpers ↔ one cloud brain ↔ local device edges ↔ devices.

Today, the brain and device modules still share the Mac process. A cloud host must be selected before separating device drivers into a local process. Cloud provider, protocol, store, runtime and migration choices remain open. There is no brain-data replication or standby system.
